## 一、设计原则

- **窄表宽列**：以 `time` 为分区维，`device_no` / `metric` 为标签（tag），`value` + `quality` 为值。
- **标签字典化**：设备/指标元数据存业务库（mdm/device），时序库只存编码，避免宽表膨胀。
- **超表分块**：按时间（如 1 天）自动分块（chunk），热数据在高速存储、冷数据压缩/降采样。
- **连续聚合**：预计算 1min/5min/1h  rollup，大屏与统计直接查聚合表，减负原始超表。
- **只追加**：时序数据为不可变事实，更新极少；点位修正走"补数"而非 UPDATE。

## 二、核心超表（Hypertable）

### 2.1 设备点位原始时序 `ts_device_metric`

```sql
CREATE TABLE ts_device_metric (
    time        TIMESTAMPTZ NOT NULL,
    tenant_id   VARCHAR(32)  NOT NULL,        -- 园区/租户
    device_no   VARCHAR(64)  NOT NULL,         -- 设备位号(关联 device-svc)
    metric      VARCHAR(32)  NOT NULL,         -- level/temp/pressure/gas...
    value       DOUBLE PRECISION NOT NULL,     -- 数值
    unit        VARCHAR(16),
    quality     SMALLINT NOT NULL DEFAULT 0,   -- 0 GOOD/1 BAD/2 UNCERTAIN (OPC UA)
    source      VARCHAR(16)  NOT NULL DEFAULT 'OPC_UA'
);

SELECT create_hypertable('ts_device_metric', 'time',
       chunk_time_interval => INTERVAL '1 day',
       partitioning_column => 'tenant_id',    -- 多租户子分区
       number_partitions => 4);
```

> 对应 Kafka `iot.raw` 落库；点位由 `iot-ingest-svc` 写入。

### 2.2 重大危险源实时参数 `ts_hazard_param`

（从设备点位按危险源维度投影，便于 B2 看板直查）

```sql
CREATE TABLE ts_hazard_param (
    time        TIMESTAMPTZ NOT NULL,
    tenant_id   VARCHAR(32) NOT NULL,
    hazard_id   VARCHAR(32) NOT NULL,         -- 重大危险源(关联 mdm)
    metric      VARCHAR(32) NOT NULL,         -- 液位/温度/压力/可燃/有毒
    value       DOUBLE PRECISION NOT NULL,
    threshold   DOUBLE PRECISION,             -- 阈值(冗余存便于越限判定)
    is_alarm    BOOLEAN DEFAULT FALSE
);

SELECT create_hypertable('ts_hazard_param', 'time',
       chunk_time_interval => INTERVAL '1 day',
       partitioning_column => 'tenant_id', number_partitions => 4);
```

### 2.3 环保监测 `ts_env_monitor`

```sql
CREATE TABLE ts_env_monitor (
    time        TIMESTAMPTZ NOT NULL,
    tenant_id   VARCHAR(32) NOT NULL,
    point_id    VARCHAR(32) NOT NULL,         -- 监测点(HJ212 地址, 关联 env-svc)
    category    VARCHAR(16) NOT NULL,         -- AIR/WATER/NOISE/VOC
    metric      VARCHAR(32) NOT NULL,         -- COD/NH3/SO2/PM25...
    value       DOUBLE PRECISION NOT NULL,
    std_limit   DOUBLE PRECISION,             -- 排放标准限值
    is_over     BOOLEAN DEFAULT FALSE
);

SELECT create_hypertable('ts_env_monitor', 'time',
       chunk_time_interval => INTERVAL '1 day',
       partitioning_column => 'tenant_id', number_partitions => 4);
```

### 2.4 能源与碳排 `ts_energy_meter`

```sql
CREATE TABLE ts_energy_meter (
    time        TIMESTAMPTZ NOT NULL,
    tenant_id   VARCHAR(32) NOT NULL,
    enterprise_id VARCHAR(32) NOT NULL,       -- 企业(关联 mdm)
    energy_type VARCHAR(16) NOT NULL,         -- ELEC/WATER/STEAM/GAS
    value       DOUBLE PRECISION NOT NULL,    -- 计量值
    power       DOUBLE PRECISION,             -- 实时功率(电)

SELECT create_hypertable('ts_energy_meter', 'time',
```

### 2.5 定位轨迹 `ts_location_track`

（人员 UWB / 车辆 GPS，写入频率高，单独超表）

## 三、连续聚合（Continuous Aggregate）

预计算大屏与统计所需 rollup，避免实时扫描原始超表。

### 3.1 设备点位 5 分钟聚合

```sql
CREATE MATERIALIZED VIEW v_device_metric_5m
WITH (timescaledb.continuous) AS
SELECT
    tenant_id,
    device_no,
    metric,
    time_bucket('5 minutes', time) AS bucket,
    avg(value)  AS avg_val,
    max(value)  AS max_val,
    min(value)  AS min_val,
    count(*)    AS cnt
FROM ts_device_metric
GROUP BY tenant_id, device_no, metric, bucket;

-- 每 1 分钟刷新
SELECT add_continuous_aggregate_policy('v_device_metric_5m',
       start_offset => INTERVAL '1 hour',
       end_offset   => INTERVAL '1 minute',
       schedule_interval => INTERVAL '1 minute');
```

### 3.2 重大危险源 1 分钟聚合（供 B2 看板）

```sql
CREATE MATERIALIZED VIEW v_hazard_param_1m
WITH (timescaledb.continuous) AS
SELECT
    tenant_id, hazard_id, metric,
    time_bucket('1 minute', time) AS bucket,
    avg(value) AS avg_val, max(value) AS max_val,
    bool_or(is_alarm) AS has_alarm
FROM ts_hazard_param
GROUP BY tenant_id, hazard_id, metric, bucket;

SELECT add_continuous_aggregate_policy('v_hazard_param_1m',
       start_offset => INTERVAL '2 hours',
       end_offset   => INTERVAL '1 minute',
       schedule_interval => INTERVAL '1 minute');
```

### 3.3 环保/能碳小时聚合

```sql
CREATE MATERIALIZED VIEW v_env_1h
WITH (timescaledb.continuous) AS
SELECT tenant_id, point_id, category, metric,
       time_bucket('1 hour', time) AS bucket,
       avg(value) AS avg_val, max(value) AS max_val,
       bool_or(is_over) AS has_over
FROM ts_env_monitor
GROUP BY tenant_id, point_id, category, metric, bucket;

CREATE MATERIALIZED VIEW v_energy_1h
WITH (timescaledb.continuous) AS
SELECT tenant_id, enterprise_id, energy_type,
       time_bucket('1 hour', time) AS bucket,
       sum(value) AS total, avg(power) AS avg_power,
       sum(carbon_equiv) AS carbon_total
FROM ts_energy_meter
GROUP BY tenant_id, enterprise_id, energy_type, bucket;
```

## 四、保留策略与压缩

```sql
-- 原始点位：热 30 天 → 压缩；冷数据降采样后保留
SELECT add_compression_policy('ts_device_metric', INTERVAL '7 days');
SELECT add_retention_policy ('ts_device_metric', INTERVAL '180 days');

SELECT add_compression_policy('ts_hazard_param', INTERVAL '7 days');
SELECT add_retention_policy ('ts_hazard_param', INTERVAL '365 days');

SELECT add_compression_policy('ts_env_monitor', INTERVAL '7 days');
SELECT add_retention_policy ('ts_env_monitor', INTERVAL '365 days');

SELECT add_compression_policy('ts_location_track', INTERVAL '3 days');
SELECT add_retention_policy ('ts_location_track', INTERVAL '90 days');

-- 连续聚合：5min 保留 30 天，1h 长期保留
SELECT add_retention_policy ('v_device_metric_5m', INTERVAL '30 days');
SELECT add_retention_policy ('v_energy_1h', INTERVAL '730 days');
```

> 压缩采用 TimescaleDB 原生列存（列式压缩 + 字典编码），点位类数据可压缩 10x+。

## 五、关键索引与查询示例

### 5.1 索引

TimescaleDB 对 `time` 自动建分区索引；业务查询补充复合索引：

```sql
CREATE INDEX idx_device_metric_dm
  ON ts_device_metric (tenant_id, device_no, metric, time DESC);

CREATE INDEX idx_hazard_param_hm
  ON ts_hazard_param (tenant_id, hazard_id, metric, time DESC);

CREATE INDEX idx_env_point
  ON ts_env_monitor (tenant_id, point_id, time DESC);

CREATE INDEX idx_location_obj
  ON ts_location_track (tenant_id, obj_type, obj_id, time DESC);
```

### 5.2 查询示例

**① 重大危险源最近 1 小时曲线（B2 看板，10s 刷新）**

```sql
SELECT time, metric, value, is_alarm
FROM ts_hazard_param
WHERE tenant_id = $1 AND hazard_id = $2
  AND time > now() - INTERVAL '1 hour'
ORDER BY time DESC;
```

**② 历史趋势回溯（拖拽时间轴）**

```sql
SELECT time_bucket('1 minute', time) AS t, avg(value) AS v
FROM ts_hazard_param
WHERE tenant_id = $1 AND hazard_id = $2 AND metric = $3
  AND time BETWEEN $4 AND $5
GROUP BY t ORDER BY t;
```

**③ 环保超标统计（C2 溯源/统计）**

```sql
SELECT point_id, count(*) FILTER (WHERE is_over) AS over_cnt,
       count(*) AS total_cnt
FROM ts_env_monitor
WHERE tenant_id = $1 AND time > now() - INTERVAL '1 day'
GROUP BY point_id;
```

**④ 区域人数实时统计（B8）**

```sql
SELECT zone, count(DISTINCT obj_id) AS person_cnt
FROM ts_location_track
WHERE tenant_id = $1 AND obj_type = 'PERSON'
  AND time > now() - INTERVAL '1 minute'
GROUP BY zone;
```

## 六、与业务库的关系

```
业务库(PostgreSQL)                时序库(TimescaleDB)
─────────────────                ───────────────────
mdm: 设备/危险源主数据     ──1:N──▶ ts_device_metric.device_no
device: 设备档案/健康       ──1:N──▶ ts_hazard_param / ts_location_track
monitor: 预警/阈值规则      ──关联──▶ ts_hazard_param (is_alarm 派生)
env: 监测点/排口           ──1:N──▶ ts_env_monitor.point_id
energy: 碳配额/核算         ──关联──▶ ts_energy_meter (carbon_equiv 汇总)
```

- **主数据在业务库，时序只存编码**：设备名/量程/责任人等从业务库 JOIN 获取，避免冗余。
- **告警派生**：`monitor-svc` 消费 `iot.raw`，比对阈值后写业务库 `warning` 表，同时可在时序写 `is_alarm` 便于检索。
- **回溯联动**：历史告警详情页同时查业务库（告警记录）+ 时序库（参数曲线）。

## 七、多租户与分区

- **单园区私有化**：`tenant_id` 可固定，超表仅按 `time` 分区即可。
- **SaaS 多园区**：`tenant_id` 作为子分区键（见建表语句 `partitioning_column`），配合行级权限（JDBC Filter 注入 `tenant_id`）实现数据隔离。
- **写入路径**：`iot-ingest-svc` → Kafka `iot.raw` → 消费者批量 `COPY`/INSERT 落超表；批量写入降低 WAL 压力。
- **读路径**：大屏 `ioc-svc` 直查连续聚合视图，监控服务查原始超表（带时间下推）。
